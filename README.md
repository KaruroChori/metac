## Soooo... what is this abomination?

Well kid, have you ever wanted real compile-time code for your C and C++ codebase?  
Running true C(++) code at compile time for C(++) programs, none of that string interpolation using an external templating language?  
Have you ever wanted to unlock the ULTIMATE POWER?  

Sorry mate, you are not assured to be the senate while using this preprocessor, but there is not evidence you cannot.

## How to use this unholy machinery?

There are a few special macros which are introduced by this preprocessor:

- `$eval` run whatever code is passed in there at compile-time and replace this macro with that.
- `$emit` pasta the string generated by the code run at compile-time and replace this macro with that.
- `$exec_eval` run a program and replace this macro with its returned value in stdout.
- `$exec_emit` run a program and paste the output on stdout replacing this macro.
- `$if_comptime` code emitted only if running at compile time (no errors can be emitted).
- `$comptime_only` code emitted only if running at compile time.

This library tries to keep complexity as low as reasonable; most of the codegen utilities is delegated downstream.

## How does it work?

The principle is actually quite simple.  
The `metac` preprocessor takes your source code, checks for special macros inside, and will add extra functions at the end for each one of those, calling them from where the original `$macros` were placed.  
This code will be compiled and linked.  
Next, `metac` will run again against the original source, but linking what was built before. This way, during this build step, we run whatever code we wanted and fill in the original sourcecode with that output.  
The final result is a modified version of our original source where all special macros have been replaced by the result of whatever complex operation we wanted, all expressed in C/C++.

In practice, it is a bit more complex.  
Our preprocessor operates before the C preprocessor can, preventing visibility of our meta code between different files since `include`s are not resolved.  
For this reason, `metac` has the option to also generate a Makefile based on a json file, but you might want to roll out your own solution by wrapping the usage of `metac` in a build system like xmake.
